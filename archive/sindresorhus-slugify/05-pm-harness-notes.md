# 05. PM·Harness 운영 메모

## 추천

URL·파일명·ID의 정규화가 목적이라면 기본 `slugify`를 **결정론적 문자열 정규화 단계**로만 사용하고, 유일성·저장·승인·충돌 해결은 상위 서비스가 소유하는 구조를 추천한다. 이유는 기본 함수가 문자열만 반환하고 저장소나 전역 상태를 갖지 않으며, 내장 카운터도 반환된 함수 하나의 메모리 `Map`에만 상태를 두기 때문이다. [S4]

이 구분은 특히 여러 서버, 재시작, 여러 작업자가 같은 ID를 만들 수 있는 서비스에서 중요하다. 카운터를 전역 유일성 도구로 쓰면 프로세스별 상태가 갈라지거나 재시작 후 번호가 초기화될 수 있다. 이는 코드 구조에서의 **추론**이며, 실제 서비스의 저장·동시성 구현은 이 레포 범위 밖이다. [S4]

## 확인된 입력 계약과 실행 단위

- 기본 실행 단위는 `slugify(string, options?)` 한 번의 동기 호출이다. 입력이 문자열이 아니면 `TypeError`로 즉시 실패한다. [S4]
- 주요 제품 선택지는 구분자, 소문자화, camelCase 분리, 사용자 정의 치환, 선행 `_`·후행 `-` 보존, 보존 문자, locale, 전사 여부다. 옵션 정의와 예시는 [01-docs/readme.ko.md](01-docs/readme.ko.md)에 번역했다. [S3], [S6]
- `transliterate: false`는 비 ASCII를 보존할 수 있어 전사가 불필요한 경우 성능상 유리할 수 있다는 README 설명이 있다. 단, 이 경우 내장 `& → and` 같은 기본 치환은 적용되지 않고 사용자 지정 치환만 직접 적용된다. [S3], [S4], [S7]
- `preserveCharacters`에 `separator`를 같이 넣으면 오류다. 구성 UI가 있다면 이 조합을 저장 전에 막는 편이 낫다. [S4], [S7]

## 사람 승인 지점과 권한

이 레포에는 에이전트·도구 호출·승인 UI·파일/DB 쓰기·네트워크 호출 경로가 확인되지 않는다. 따라서 라이브러리 자체의 승인 단계는 없고, 어느 문자열을 공개 URL/파일명/영구 식별자로 채택할지, 충돌시 기존 데이터를 덮어쓸지 같은 되돌리기 어려운 결정은 **호출 서비스**가 승인·감사 로그와 함께 소유해야 한다. 전자는 코드 근거의 사실이고, 후자는 Harness 설계를 위한 **추천**이다. [S2], [S4]

## 증거·검증 기준

- 기능 단위 증거: 반환 문자열, 또는 명시적 `TypeError`/`Error`다. [S4]
- 회귀 방지 계약: `test.js`는 camelCase, 아포스트로피, 사용자 치환, 구분자, 여러 문자권, locale, 전사 해제, 카운터, 오류를 다룬다. [S7]
- 자동화 정의: CI는 push·PR마다 Node 20·24에서 `npm install`과 `npm test`를 실행한다. [S8]
- **미검증**: 이 아카이브는 읽기 전용 API 절차여서 고정 SHA에서 의존성 설치·테스트를 실제 실행하거나 CI run 로그를 확인하지 않았다. 따라서 "테스트가 있다"와 "현재 CI가 통과했다"를 구분해야 한다. [S7], [S8]

## 재실행·복구 판단

기본 함수는 현재 파일에서 외부 상태를 읽거나 기록하지 않아, 같은 문자열·옵션이면 같은 결과가 기대되는 계산 경로다. 반면 카운터는 인스턴스별 이전 호출 기록을 사용하므로, 재시도 전에 같은 인스턴스를 유지할지·새로 만들지·`reset()`할지를 호출자가 정해야 한다. `reset()`은 복구 동작이 아니라 그 인스턴스의 중복 번호 기록을 지우는 동작이다. [S4]

## Harness에 연결할 때의 권장 계약

1. 입력 원문, 적용 옵션, 라이브러리 버전/고정 SHA, 반환 slug를 같은 작업 로그에 남긴다. 그러면 locale·치환 옵션 때문에 결과가 바뀐 경우를 재현할 수 있다. **추천**
2. 생성한 slug를 영구 ID나 공개 URL에 쓰기 전, 저장소의 unique 제약 또는 예약 API로 충돌을 확인한다. 충돌 시 재시도 규칙은 카운터 숫자에 암묵적으로 맡기지 말고 제품 정책으로 명시한다. **추천**
3. 사용자 정의 치환과 보존 문자는 URL·파일명 정책에 영향을 주므로, 허용 목록·미리보기·검증 오류를 제공한다. 특히 보존 문자와 구분자 충돌은 라이브러리도 오류로 거부한다. **추천**, 오류 근거는 [S4]
4. 배포 게이트에서는 `npm test`가 `xo && ava`를 실제로 통과했는지와 Node 20·24 호환성을 확인한다. 현재 아카이브는 워크플로 설정만 확인했으므로 실행 로그가 별도 증거로 필요하다. **추천**, 설정 근거는 [S3], [S8]

## 확장 지점과 미확인 사항

확인된 확장 지점은 `customReplacements`, `preserveCharacters`, `locale`, `transliterate` 옵션이다. 외부 전사 패키지가 실제로 지원하는 모든 언어·locale 표, 성능 한계, npm 패키지 배포본, 보안 이력은 열지 않았으므로 이 아카이브는 그 특성을 보증하지 않는다. [S3], [S4], [S6]
