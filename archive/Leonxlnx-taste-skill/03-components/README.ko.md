# 구성요소: 스킬 정의 한국어 해설

이 저장소에는 별도 agent 정의 파일이 없고 `skills/` 아래 13개 `SKILL.md`가 있다. 아래는 각 정의의 frontmatter 설명과, 실제로 읽은 핵심 절차·출력 계약을 한국어로 옮긴 것이다. 가장 긴 4개 정의의 전체 본문을 줄 단위로 완역한 문서는 아니다. 열지 않은 절은 해석에 사용하지 않았으며, 모든 원문 위치는 [06-source-evidence.md](../06-source-evidence.md)에서 확인할 수 있다.

## 구현 및 리디자인 계열

### `design-taste-frontend` - 기본 `taste-skill` v2 experimental

랜딩 페이지·포트폴리오·리디자인을 위한 anti-slop 프런트엔드 스킬이다. brief를 읽어 디자인 방향을 추론하고, 템플릿처럼 보이지 않는 인터페이스를 만들며, 필요한 경우 실제 디자인 시스템을 사용하고 리디자인은 감사부터 하며 엄격한 pre-flight를 요구한다.

입력은 brief, 참조물, 사용자층, 브랜드 자산, 조용한 제약이다. 먼저 한 줄 Design Read와 세 다이얼(다양성·모션·밀도)을 정하고, 실제 시스템이면 공식 패키지를 선택한다. 출력 전에 접근성/성능/reduced motion/다크 모드와 긴 체크리스트를 통과하도록 지시한다. 대시보드·데이터 테이블·다단계 폼·네이티브 모바일·실시간 협업은 이 스킬의 주 대상이 아니라고 명시한다. [E09][E10][E11][E12]

### `design-taste-frontend-v1` - 이전 기본값 보존판

기존 v1 동작에 의존하는 프로젝트를 위한 원본 보존판이다. 기본 8/6/4 다이얼, React/Next.js·Tailwind·의존성 확인, AI 디자인 상투어 회피, 모션·성능 가드레일, 출력 전 확인을 정의한다. 새 기능보다는 정확한 하위 호환이 필요할 때 쓰라는 계약이다. [E07][E13]

### `gpt-taste` - GPT/Codex용 강한 변형

고급 GSAP 모션과 높은 레이아웃 다양성을 강제하는 UX/UI 지시문이다. `<design_plan>` 안에서 사용자 프롬프트 길이 등을 seed로 한 “Python randomization”을 시뮬레이션해 hero, 글꼴, 컴포넌트, GSAP 방식을 고르고, AIDA(Attention-Interest-Desire-Action) 페이지 구조와 큰 섹션 간격을 요구한다. 실제 Python 실행이나 난수 결과의 저장은 정의에서 확인되지 않는다. [E14]

### `redesign-existing-projects` - 기존 프로젝트 개선

기존 코드베이스를 먼저 읽어 프레임워크·스타일링·현재 패턴을 파악하고, 문제를 감사한 뒤, 재작성 대신 현재 스택 안에서 표적 개선하라고 한다. 글꼴, 색, 상호작용, 레이아웃, 상태, 의미론 HTML, alt, meta를 점검한다. 수정 우선순위는 font swap → 색 정리 → hover/active → 레이아웃/간격 → 일반 컴포넌트 교체 → loading/empty/error → 타이포그래피 마감이며, 기능을 깨지 말고 매 변경 후 테스트하라고 한다. [E19]

### `high-end-visual-design` - 부드러운 고급 UI

고급 에이전시 스타일의 폰트·여백·그림자·카드·애니메이션 규칙을 주는 스킬이다. 분위기와 레이아웃 archetype을 고른 뒤 texture, macro whitespace, 이중 테두리 구조, 모션을 순서대로 구현하고 사전 체크를 한다. `transform`/`opacity` 외 애니메이션과 스크롤 컨테이너 blur/noise를 금지해 성능 경계를 둔다. [E20]

### `minimalist-ui` - 편집 디자인형 미니멀 UI

따뜻한 단색 계열, 큰 타이포그래피 대비, 평면 bento grid, 절제된 파스텔을 사용하는 인터페이스 지시문이다. 기본 글꼴·무거운 그림자·강한 배경색·gradient·대형 pill·이모지·placeholder 이름·AI식 문구를 금지하고, 얇은 경계와 여백 중심의 컴포넌트를 요구한다. [E22]

### `industrial-brutalist-ui` - 산업적 브루탈리즘

스위스 인쇄와 전술 텔레메트리/CRT라는 두 시각 모드 중 하나를 프로젝트별로 고정하는 스킬이다. CSS Grid, 기계적 타이포그래피·경계·ASCII 장식, 하프톤/scanline 같은 질감을 정의하며 의미론 HTML과 `clamp()`를 권한다. ‘무작위 문자열’ 같은 표현은 실제 데이터가 아니라 시각적 연출 지시일 뿐임에 유의해야 한다. [E21]

## 이미지 우선 및 이미지 전용 계열

### `image-to-code` - 이미지 → 분석 → 코드

시각 품질이 중요한 웹 작업에서 먼저 별도 섹션 참조 이미지를 만들고, 텍스트·타이포그래피·간격·색·레이아웃·버튼을 분석한 뒤 그 이미지에 충실하게 코드를 구현하도록 하는 Codex용 지시문이다. 기존 이미지를 crop하는 대신 필요한 상세 이미지를 새로 만들고, 구현에서 일반 템플릿으로 drift하지 말라고 한다. [E15]

### `imagegen-frontend-web` - 웹 참조 이미지

코드를 쓰지 않는 웹 이미지 생성 스킬이다. 요청 섹션 수만큼 **가로 이미지 한 장씩**을 만들고, 여러 섹션을 한 보드나 긴 한 장에 압축하지 않는다. 섹션별 구성은 달라도 팔레트·글꼴·CTA·반경·이미지 처리는 하나의 브랜드 세계로 유지하라고 한다. [E16]

### `imagegen-frontend-mobile` - 모바일 화면/흐름 참조 이미지

코드를 쓰지 않고 iOS/Android/중립 앱의 화면 세트를 생성하는 지시문이다. 화면 수를 줄여 합성 보드로 만들지 말고, 여러 화면이면 플랫폼·기기 프레임·팔레트·타입·간격·컴포넌트·탐색 모델을 포함한 내부 design bible을 고정한다. 흐름의 순서와 화면 간 일관성·가독성·safe area를 검사한다. [E17]

### `brandkit` - 브랜드 키트 보드 이미지

로고 방향, 색·타이포그래피, 아이덴티티 적용, mockup을 담은 고급 브랜드 키트 이미지를 만드는 스킬이다. 일반 로고·무작위 mockup·지저분한 AI moodboard를 만들지 말고 하나의 이미지에 완결된 브랜드 세계를 만들라고 한다. [E18]

## 출력 보완 및 전달 형식 계열

### `full-output-enforcement` - 완전 출력 강제

부분 응답, placeholder comment, skeleton만 제시하는 행동을 실패로 간주한다. 요청 산출물의 수를 세고, 모두 완전하게 만들고, 마지막에 원 요청과 대조한다. 토큰 한도에 접근하면 품질을 압축하지 말고 자연스러운 경계에서 pause 문구로 이어서 생성하도록 한다. [E26]

### `stitch-design-taste` - Stitch용 DESIGN.md 생성

Google Stitch 화면 생성을 위해 자연어 기반 `DESIGN.md`를 생성하는 스킬이다. 분위기, 색, 글꼴, 컴포넌트, 레이아웃, 모션 의도, 금지 패턴을 의미론적으로 쓰도록 한다. 전제 조건으로 Google Stitch 접근과 선택적인 Stitch MCP Server를 언급하지만 이 저장소는 연결이나 인증을 구현하지 않는다. [E24]

### `skills/stitch-skill/DESIGN.md` - 제공된 Taste Standard 예시

실제 기본값 예시 문서다. 창의성·밀도·다양성·모션 의도 다이얼을 조정하도록 하고, 색과 글꼴·레이아웃·반응형·모션 의도를 구체 수치로 제공한다. 이는 템플릿/참조 문서이며, 실시간 생성이나 테스트 결과는 아니다. [E25]
