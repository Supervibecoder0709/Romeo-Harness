# 워크플로우 요약

## 무엇을 하는가

Taste Skill은 실행 프로그램이 아니라 AI 에이전트에 주입하는 프런트엔드 디자인·생성 지시문 모음이다. 기본 `taste-skill` v2는 랜딩 페이지, 포트폴리오, 리디자인을 대상으로 하고, 별도 스킬은 기존 UI 개선, 이미지 우선 구현, 웹/모바일/브랜드 참조 이미지, Google Stitch용 `DESIGN.md`, 출력 누락 방지를 맡는다. [E03][E08][E09]

## 입력

**확인된 입력 계약**은 자연어 brief와, 가능한 경우 기존 프로젝트·참조 URL/스크린샷·브랜드 자산·대상 사용자·제약이다. 기본 v2는 페이지 종류, 분위기 단어, 참고물, 사용자층, 기존 브랜드 자산, 규제/접근성 제약을 읽고 한 줄의 “Design Read”를 내도록 요구한다. 불확실해서 디자인 방향이 실제로 갈릴 때만 질문 하나를 하라고 한다. [E09]

`image-to-code`는 시각 품질이 핵심이고 이미지 생성이 가능한 환경을 전제로 한다. 웹 이미지 스킬은 섹션 수, 모바일 이미지 스킬은 앱 범주·플랫폼·화면 수를 입력으로 추론한다. [E15][E16][E17]

## 처리 단계

### A. 일반 프런트엔드 / 리디자인: `taste-skill` v2

1. brief를 해석하고, `DESIGN_VARIANCE` / `MOTION_INTENSITY` / `VISUAL_DENSITY` 3개 다이얼을 정한다. [E09]
2. 실제 디자인 시스템에 해당하면 공식 패키지를, 미적 스타일이면 CSS/라이브러리 조합을 사용하되 공식 시스템인 척하지 않도록 지시한다. [E10]
3. React/Next.js, Tailwind, Motion 등의 기본 규칙과 의존성 확인 규칙을 적용한다. 이들은 권장 지시일 뿐, 이 저장소가 설치하는 의존성은 아니다. [E10]
4. 리디자인이면 greenfield / preserve / overhaul을 먼저 분류하고, 브랜드·IA·SEO·접근성·분석 이벤트를 감사한다. URL, 주 메뉴, 폼 필드, 로고, 법률/동의 문구는 명시 승인 없이 바꾸지 말라고 한다. [E12]
5. 코드 출력 전 사전 점검표를 통과시키는 것이 정의상 완료 조건이다. 성능·reduced motion·다크 모드·Lighthouse도 요구한다. [E11][E12]

### B. 이미지 우선 웹 구현: `image-to-code`

1. 섹션 수를 정하고 섹션별 참조 이미지를 생성한다.
2. 작은 텍스트/컴포넌트 등 불명확한 부분은 새 detail 이미지를 생성하며, 기존 보드의 crop으로 대체하지 않는다.
3. 이미지에서 텍스트, 타이포그래피, 간격, 색, 레이아웃, 버튼, 컴포넌트 논리를 읽는다.
4. 참조 이미지에 충실한 코드를 구현하고, 이미지를 평범한 템플릿으로 바꾸는 design drift를 금지한다. [E15]

### C. 이미지 전용 출력

- 웹: 모든 섹션당 가로 이미지 1장. 수량이 불명확하면 landing 6장, full website 8장 등의 기본값을 쓴다. 모든 프레임이 하나의 브랜드 세계로 보이게 한다. [E16]
- 모바일: 요청 화면 수만큼 화면 이미지를 생성하고, 여러 화면이면 디자인 bible을 잠가 일관된 앱 흐름과 기기 프레임을 유지한다. 코딩 모드로 전환하지 말라고 명시한다. [E17]
- 브랜드: 하나의 프레젠테이션형 브랜드 키트 이미지에서 로고, 색, 타이포그래피, 적용물을 구성하도록 지시한다. [E18]

## 출력/상태

이 저장소가 직접 저장하거나 변경하는 상태는 확인되지 않았다. 기대 출력은 스킬에 따라 다음 중 하나다.

| 스킬 계열 | 정의상 기대 산출물 | 저장·게시 상태 |
| --- | --- | --- |
| 구현형 | 프런트엔드 코드 또는 기존 코드의 개선 | `UNVERIFIED`: 실행 에이전트와 대상 프로젝트가 처리 |
| image-to-code | 참조 이미지 분석 후 구현 코드 | `UNVERIFIED`: 이미지/코드 생성 도구가 처리 |
| 이미지형 | 웹 섹션, 모바일 화면, 브랜드 보드 이미지 | `UNVERIFIED`: 이미지 생성 도구가 처리 |
| Stitch | `DESIGN.md` | `UNVERIFIED`: Stitch 또는 사용자가 처리 |
| output | 누락 없는 응답 | 대화 출력만, 영속 상태 없음 |

## 실패·재시도

**정의에 있는 재시도 지시.** 이미지가 불명확하면 새 독립 이미지/상세 렌더를 생성하고, 화면 품질 체크에서 실패하면 refine하라고 한다. 긴 출력이 한도에 닿으면 자연스러운 경계에서 `[PAUSED — X of Y complete...]`로 중단하고 `continue`에서 재개하도록 한다. [E15][E17][E26]

**정의에 없는 항목.** 자동 retry 횟수, 실패 분류, 지수 백오프, idempotency key, 작업 큐, 버전된 산출물, rollback, 동시 실행 충돌 처리는 고정 트리에서 확인되지 않았다.

## 관찰 증거

스킬 본문은 코드 제출 전 체크리스트, dependency 확인, Lighthouse, 그리고 motion/reduced-motion 등을 요구한다. 그러나 저장소에는 실행 명령, CI, 테스트, 결과 로그가 없어 이 요구가 실제로 수행됐는지 증명할 수 없다. 따라서 Harness에서 완료로 판단하려면 최소한 **실제 변경 파일 diff, 빌드/테스트 로그, 지정 화면의 스크린샷, 접근성·성능 측정값, 이미지/코드 결과의 경로**를 작업별로 별도 수집해야 한다. 이 마지막 문장은 저장소의 구현이 아니라 운영상 **추천**이다.
