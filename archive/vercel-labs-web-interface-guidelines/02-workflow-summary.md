# 워크플로우 요약

## 무엇을 하는가

이 레포는 웹 인터페이스를 직접 빌드·호스팅하지 않는다. 대신 접근성, 입력·상태, 모션, 성능, 카피에 관한 정적 가이드라인과, AI가 UI 코드를 점검할 때 사용할 명령 프롬프트를 제공한다. [E02]–[E05]

## 입력

- **규칙 적용:** 프로젝트의 `AGENTS.md`에 내용을 추가하거나, 사람이 `README.md`를 기준으로 구현·검토한다. [E02][E03]
- **AI 검토:** 명령의 `<file-or-pattern>` 인수로 대상 파일/패턴을 전달한다. 프롬프트 내부에서는 이를 `$ARGUMENTS`로 참조한다. [E04]
- **로컬 설치(선택):** 사용자가 셸에서 `install.sh`를 실행하면, 스크립트가 로컬 파일 시스템에서 지원 도구의 존재를 감지한다. [E06][E07]

## 처리 단계

1. 검토 명령은 대상 파일을 읽고, 접근성·포커스·폼·애니메이션·성능·상태·국제화 등 규칙에 대조하도록 지시한다. [E04]
2. 결과는 파일별로 묶고 `file:line - 문제` 형식으로 출력한다. 설명은 수정이 명확하지 않을 때만 요구하며, 통과 파일에는 `✓ pass`를 쓰도록 정했다. [E05]
3. 설치 스크립트는 Amp Code, Claude Code, Cursor, OpenCode, Windsurf, Antigravity, Gemini CLI의 존재를 각각 검사한다. 감지된 도구에는 `command.md` 원문을 그대로 저장하거나 도구가 요구하는 `SKILL.md`/TOML 형식으로 변환한다. [E07]–[E10]
4. 감지된 도구가 하나도 없으면 지원 도구 목록을 출력하고 상태 1로 끝낸다. 하나 이상이면 완료 메시지와 `/web-interface-guidelines <file>` 사용 예시를 출력한다. [E11]

## 출력/상태

- 검토 명령의 기대 출력은 사람이 바로 이동할 수 있는 `file:line` 결함 목록이다. 이는 프롬프트 계약이며, 실제 어느 AI 런타임에서 어떤 정확도로 수행되는지는 확인하지 않았다. [E05]
- 설치 스크립트는 사용자 홈 디렉터리 아래의 도구별 경로에 파일을 생성·덮어쓰거나(`curl -o`), Windsurf 규칙 파일에 내용을 추가한다. [E07]–[E10]
- 레포 자체는 데이터 저장소·원격 API 인증·배포 상태를 만들지 않는다. 다만 설치 스크립트는 GitHub raw URL에 네트워크 요청을 하고 로컬 파일 시스템을 변경한다. [E09]

## 실패·재시도

**확인된 사실**

- 스크립트는 `set -e`를 설정한다. 별도의 복구·재시도 로직은 원문에서 확인되지 않는다. 다만 pipeline 안의 네트워크 실패가 Bash의 `set -e`만으로 항상 어떻게 전파되는지는 실행하지 않았으므로 미검증이다. [E06][E10]
- 아무 지원 도구도 감지되지 않는 경우는 명시적으로 실패(종료 코드 1) 처리한다. [E11]
- Windsurf만 marker를 검색해 동일 블록의 중복 추가를 피하려 한다. 다른 도구 분기는 기존 파일을 덮어쓸 수 있다. [E08]

**미확인**

- 각 AI 도구가 설치한 명령을 실제 발견·실행하는지, 도구별 기존 설정과 충돌하지 않는지, 중간 실패 후 파일이 어떤 상태로 남는지는 실행하지 않았으므로 미검증이다.

## 관찰 증거

- **설치 전:** 지원 도구의 감지 조건과 대상 경로를 미리 읽어 확인한다. 스크립트에는 사전 승인·dry-run 기능이 없다. [E07]–[E10]
- **설치 후 최소 증거:** 스크립트의 성공 메시지만으로는 부족하다. 대상 경로의 파일 존재, 기대한 frontmatter/TOML 변환, 실제 도구에서 명령 발견 여부를 각각 읽어 확인해야 한다. 이는 스크립트가 해시·내용 검증을 하지 않는다는 사실에 근거한 운영상 **추천**이다. [E07]–[E11]
- **검토 완료 증거:** `command.md`가 정한 대상 파일별 `file:line` 결과 또는 `✓ pass` 출력이다. 그러나 이는 AI의 검토 출력일 뿐, 브라우저·보조기술·성능 실측을 대체하지 않는다. [E05]
