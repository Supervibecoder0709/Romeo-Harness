# PM Harness 운영 메모

## 결론: 추천 운영 방식

**추천:** 이 레포를 자동 설치 도구가 아니라, 프로젝트에 버전 고정해 넣는 UI 품질 정책 + PR/에이전트 검토 체크리스트로 사용한다. `install.sh`는 지원 도구의 전역 홈 디렉터리에 파일을 쓰고 `main`에서 비고정 내용을 내려받으므로, 팀의 재현성·변경 통제에는 커밋 SHA로 보관한 `AGENTS.md`/`command.md` 사본과 명시적 리뷰 절차가 더 적합하다. [E03]–[E05][E09]

## 확인된 입력 계약

- 생성 에이전트에는 `AGENTS.md`의 MUST/SHOULD/NEVER를 프로젝트 컨텍스트로 제공한다. 해당 파일은 접근성, 폼, 모션, 성능, 테마 등 결정을 규정한다. [E03]
- 검토 에이전트에는 `command.md`와 대상 `<file-or-pattern>`을 제공한다. 결과 계약은 파일 그룹별 `file:line` 문제 목록, 또는 `✓ pass`다. [E04][E05]
- 이는 **정적 검토 계약**이다. 가이드라인은 브라우저 화면, 키보드 실제 조작, 스크린 리더, 네트워크 성능을 자동 실행·측정하는 코드가 아니다. [E01][E04]

## 사람 승인 지점

1. **가이드라인 버전 갱신:** `main`이 아니라 사용할 SHA와 변경 차이를 사람이 승인한다. 이 레포의 설치 스크립트는 `main`을 참조한다. [E09]
2. **로컬 전역 설치:** 설치 대상 경로와 기존 파일 덮어쓰기/append 영향을 읽은 뒤 승인한다. 예를 들어 Claude/Cursor 등은 `curl -o`로 파일을 쓰고, Windsurf는 전역 규칙 파일을 수정한다. [E07][E08]
3. **예외 승인:** 제품 요구가 MUST 규칙과 충돌할 때는 예외 이유, 사용자 영향, 대체 접근성 수단, 만료 조건을 기록해 사람이 승인한다. 이는 규칙이 원칙 수준이며 코드상 예외 승인 체계는 제공하지 않는다는 사실을 전제로 한 **추천**이다. [E03]

## 실행 단위와 증거

| 단계 | 권장 단위 | 완료 증거 | 이 레포만으로 확인하지 못하는 것 |
| --- | --- | --- | --- |
| 생성 | 화면/컴포넌트 변경 단위 | 적용한 가이드 SHA와 관련 규칙 ID | 실제 렌더링·접근성 결과 |
| 정적 검토 | 파일 또는 glob 단위 | `file:line` 결과, 해결 커밋, 남은 예외 | 프롬프트 검토의 누락·오탐 |
| 사용자 검증 | 핵심 흐름 단위 | 키보드, 작은 화면, 오류/빈 상태, 보조기술, 성능 측정 결과 | 자동화되지 않은 실기기/보조기술 범위 |
| 도구 설치 | 도구별 1회 | 대상 파일의 읽기 검증 + 도구 명령 발견 확인 | 스크립트 성공 문구만으로는 설치품질 보장 불가 |

## 재시도·복구

- **확인:** 설치 스크립트에는 backup, rollback, dry-run, SHA 검증, 재시도 로직이 없다. `set -e`를 설정하지만, 이전에 쓴 파일을 되돌리는 로직은 없다. pipeline 실패가 실제로 어떤 지점에서 종료되는지는 실행하지 않아 미검증이다. [E06]–[E11]
- **추천:** 전역 설치 전 대상 파일을 별도 백업하고, 고정 SHA raw URL에서 내려받은 사본의 해시·내용을 확인한 다음 실제 AI 도구의 명령 목록을 읽어 검증한다. 실패 시 백업 복원은 되돌릴 수 있는 복구 경로다.
- **추천:** 체크리스트 위반을 단순 pass/fail로 끝내지 말고 `규칙 → 코드 위치 → 스크린샷/실측 → 예외 승인` 기록으로 연결한다. `command.md` 자체가 `file:line` 형식을 요구하므로 이 결합이 자연스럽다. [E05]

## 비용·운영·보안·이전성 판단

- **비용:** 레포 자체는 의존성·호스팅·유료 API를 포함하지 않는다. 다만 실제 검토 비용은 선택한 AI 도구/모델 사용량에 달려 있어 이 레포만으로는 산정할 수 없다. [E01][E04]
- **운영:** 단일 Markdown 규칙은 이식성이 높지만, 구현 검증·버전 갱신·예외 처리는 사용자의 Harness가 추가로 맡아야 한다. [E03]–[E05]
- **보안:** `install.sh` 실행은 홈 디렉터리 쓰기와 네트워크 다운로드를 수반한다. `main`을 신뢰해 즉시 실행하지 말고, 고정 SHA와 설치 대상 파일을 사전 확인하는 편이 안전하다. [E07]–[E10]
- **이전성:** `AGENTS.md`와 `command.md`는 평문 Markdown이므로 특정 런타임에 깊게 묶이지 않는다. 반면 `install.sh`의 경로·형식 변환은 도구별 파일 관례에 의존한다. [E03][E04][E07]–[E10]

## 확장 지점

**확인된 범위:** 이 레포에는 CI나 테스트 실행점이 없어서 자동 gate를 바로 켤 수는 없다. [E01]

**추천:** 다음 순서가 가장 안전하다.

1. 고정 SHA의 규칙을 프로젝트 내부 정책 파일로 채택한다.
2. 변경 PR마다 `command.md` 형식의 정적 검토를 실행하고, 결과를 보존한다.
3. 위험이 큰 흐름(결제·권한·삭제·폼 제출)은 브라우저 기반 키보드/오류/모바일 검증을 필수 gate로 둔다.
4. 반복 위반만 린트·테스트로 기계화하되, AI 검토 출력은 최종 증거가 아닌 보조 신호로 둔다.
