# 탐색 기록

## 범위와 방법

- 대상: `vercel-labs/web-interface-guidelines`, ref `main`, 고정 SHA `e3d624baaf29dc1fc645aff3e38f03e564d2d6b1`.
- GitHub API의 재귀 트리로 파일 목록만 먼저 확인한 뒤, 후보 5개를 GitHub raw content API로 열었다. clone·실행·설치·외부 쓰기는 하지 않았다. [E01]
- 후보가 5개뿐이므로 대형 레포 분할 인벤토리는 적용하지 않았다.

## 기술 스택 및 실행 진입점

**확인된 사실**

- 애플리케이션 프레임워크·패키지 매니저·서버·데이터베이스는 없다. 고정 SHA의 파일 트리는 위 5개 blob뿐이다. [E01]
- 실제 실행 가능한 시작점은 Bash `install.sh`다. `set -e`를 켜고, TTY일 때만 ANSI 색을 설정한 후 도구별 존재 여부를 검사한다. [E06]
- 설치 payload는 `command.md`이며, 대부분의 분기에서 `https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md`를 `curl -sL`로 가져온다. [E07][E09]
- `command.md`는 실행 코드가 아니라 AI 에이전트/명령이 따라야 할 검토 프롬프트다. 인수 형식은 `<file-or-pattern>`이고, 결과는 파일별 `file:line` 이슈 목록 또는 `✓ pass`다. [E04][E05]

**해석**

- 이 레포의 핵심 제공물은 웹 UI를 생성하거나 렌더링하는 서비스가 아니라, 사람이 프로젝트에 복사하거나 AI 도구에 설치해 사용하는 **정적 UI 품질 규칙 세트**다. 이 해석은 애플리케이션 코드 부재와 문서·프롬프트 중심 파일 구성에 근거한다. [E01]–[E05]

## 확인된 핵심 흐름

1. 팀/사용자가 `README.md` 또는 `AGENTS.md`의 UI 원칙을 프로젝트 규칙으로 채택한다. [E02][E03]
2. AI 도구에서 검토할 파일 또는 glob을 `$ARGUMENTS`로 전달한다. [E04]
3. `command.md`의 체크리스트가 접근성·폼·애니메이션·성능 등 위반 후보를 점검하고 파일·줄 기준의 간결한 결과를 요구한다. [E04][E05]
4. 선택적으로 `install.sh`가 로컬에 이미 감지된 지원 도구의 전역 경로에 이 명령 파일을 내려받거나, Windsurf 규칙 파일에 덧붙인다. [E07]–[E11]

## 문서 간 불일치와 미확인 범위

- **확인된 불일치:** `README.md`는 모바일 입력 확대 방지의 대안으로 `maximum-scale=1`이 포함된 viewport를 제시하지만 [E02], `AGENTS.md`와 `command.md`는 `maximum-scale=1`을 브라우저 확대를 막는 금지 패턴으로 명시한다. [E03][E04] 이 아카이브는 금지 규칙 쪽이 일관된 접근성 방침이라고 기록하지만, 어느 쪽이 저자의 최신 의도인지는 커밋 내부만으로 판단할 수 없다.
- 테스트·CI가 없으므로 체크리스트가 실제 UI 결함을 얼마나 검출하는지, `install.sh`의 각 분기가 현재 지원 도구 버전에서 작동하는지는 미검증이다. [E01]
- 외부 규격(WAI-ARIA, APCA 등)과 외부 링크의 현재 내용은 원문 링크만 보존했으며 이 작업에서 별도 검증하지 않았다.
