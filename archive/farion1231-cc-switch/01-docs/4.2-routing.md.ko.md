# 4.2 앱 라우팅

## 개요

앱 라우팅은 CC Switch가 특정 애플리케이션의 API 요청을 로컬 라우팅 서비스로 경유시키는 기능입니다.

라우팅을 활성화하면:
- 앱의 API 요청이 로컬 라우팅을 통해 전달됩니다.
- 요청 로그와 사용량 통계를 기록할 수 있습니다.
- 장애 조치 기능을 사용할 수 있습니다.

## 사전 조건

앱 라우팅 기능을 사용하기 전에 라우팅 서비스를 시작해야 합니다.

## 라우팅 활성화

### 위치

Settings > Advanced > Routing Service > App Routing 영역

### 단계

1. 라우팅 서비스가 시작되어 있는지 확인합니다.
2. "App Routing" 영역을 찾습니다.
3. 원하는 앱의 토글을 켭니다.

### 라우팅 토글

| 토글 | 효과 |
|--------|--------|
| Claude Routing | Claude Code 요청을 라우팅 |
| Codex Routing | Codex 요청을 라우팅 |
| Gemini Routing | Gemini CLI 요청을 라우팅 |

여러 앱의 라우팅을 동시에 활성화할 수 있습니다.

## 라우팅 작동 방식

### 설정 변경

라우팅을 활성화하면 CC Switch가 앱의 설정 파일을 수정해 API endpoint가 로컬 라우팅 서비스를 가리키도록 합니다.

**Claude 설정 변경**:

```json
// Before routing
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.anthropic.com"
  }
}

// After routing
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:15721"
  }
}
```

**Codex 설정 변경**:

```toml
# Before routing
base_url = "https://api.openai.com/v1"

# After routing
base_url = "http://127.0.0.1:15721/v1"
```

**Gemini 설정 변경**:

```bash
# Before routing
GOOGLE_GEMINI_BASE_URL=https://generativelanguage.googleapis.com

# After routing
GOOGLE_GEMINI_BASE_URL=http://127.0.0.1:15721
```

### 요청 전달

라우팅 서비스가 요청을 받으면:

1. 요청 출처(Claude/Codex/Gemini)를 식별합니다.
2. 해당 앱에 대해 현재 활성화된 공급자를 찾습니다.
3. 요청을 공급자의 실제 endpoint로 전달합니다.
4. 요청 로그를 기록합니다.
5. 응답을 앱에 반환합니다.

## 라우팅 상태 표시기

### 기본 인터페이스 표시기

라우팅이 활성화되면 기본 인터페이스에 다음 변화가 표시됩니다.

- **라우팅 로고 색상**: 무색에서 초록색으로 바뀝니다.
- **공급자 카드**: 현재 활성 공급자에 초록색 테두리가 표시됩니다.

### 공급자 카드 상태

| 상태 | 테두리 색상 | 설명 |
|-------|--------------|-------------|
| 현재 활성 | 파란색 | 설정 파일의 공급자(비라우팅 모드) |
| 라우팅 활성 | 초록색 | 라우팅이 실제로 사용하는 공급자 |
| 일반 | 기본 | 사용하지 않는 공급자 |

## 라우팅 비활성화

### 단계

1. 라우팅 패널에서 해당 앱의 라우팅 토글을 끕니다.
2. 또는 라우팅 서비스를 직접 중지합니다.

### 설정 복원

라우팅을 비활성화하면 CC Switch는 다음을 수행합니다.

1. 앱 설정을 라우팅 이전 상태로 복원합니다.
2. 현재 요청 로그를 저장합니다.

## 라우팅과 공급자 전환

### 라우팅 모드에서 공급자 전환

라우팅 모드에서 공급자를 전환할 때:

1. 기본 인터페이스에서 공급자의 "Enable" 버튼을 클릭합니다.
2. 라우팅 서비스가 즉시 새 공급자를 사용해 요청을 전달합니다.
3. **CLI 도구를 다시 시작할 필요가 없습니다.**

이는 라우팅 모드의 큰 장점입니다. 공급자 전환이 즉시 적용됩니다.

### 라우팅 없이 전환

라우팅 없이 공급자를 전환할 때:

1. 설정 파일이 수정됩니다.
2. 변경 사항을 적용하려면 CLI 도구를 다시 시작해야 합니다.

## 다중 앱 라우팅

여러 앱을 동시에 라우팅할 수 있으며, 각각 독립적으로 관리됩니다.

- 독립적인 공급자 설정
- 독립적인 장애 조치 큐
- 독립적인 요청 통계

## 사용 사례

### 시나리오 1: 사용량 모니터링

라우팅 + 로그 기록을 활성화해 API 사용량을 모니터링합니다.

### 시나리오 2: 빠른 전환

라우팅을 활성화하면 CLI 도구를 다시 시작하지 않고 공급자를 전환할 수 있습니다.

### 시나리오 3: 장애 조치

장애 조치 기능을 사용하기 위한 사전 조건은 라우팅 활성화입니다.

## 참고

### 성능 영향

라우팅은 최소한의 지연(일반적으로 < 10ms)을 추가하며, 대부분의 상황에서 무시할 수 있습니다.

### 네트워크 요구 사항

라우팅 모드에서는 CLI 도구가 로컬 라우팅 주소에 접근할 수 있어야 합니다.

### 설정 백업

라우팅을 활성화하기 전에 CC Switch는 원래 설정을 백업하고, 비활성화할 때 복원합니다.

## FAQ

### 라우팅을 활성화한 뒤 요청이 실패합니다

다음을 확인합니다.
- 라우팅 서비스가 정상적으로 실행 중인가요?
- 공급자 설정이 올바른가요?
- 네트워크가 정상적으로 동작하나요?

### 라우팅을 비활성화한 뒤 설정이 복원되지 않습니다

가능한 원인:
- 라우팅 서비스가 비정상적으로 종료되었습니다.
- 다른 프로그램이 설정 파일을 수정했습니다.

해결 방법:
- 공급자를 수동으로 편집하고 다시 저장합니다.
- 또는 라우팅을 다시 활성화한 뒤 비활성화합니다.
