## 2. 두 분석의 대조와 코디네이터 판정

**합의된 사실 (양쪽 + 재현):**
1. 동등성 게이트의 검토자 면은 LLM 의 자유 서술 판정(`gate_verdict`) 일치를 요구하는데, 같은 산출물·같은 런타임에서도 판정이 바뀐다(D-74 관측). 그래서 게이트는 "같은 실패 문자열" 도 PASS 로 세고, 표본을 늘려도 참값이 생기지 않는다.
2. 그 관측 뒤 게이트 정의가 12시간 안에 세 번 바뀌었고(D-73 → D-74 → D-75), 매번 요구 실행 수와 봉인·결박 장치가 늘었다. 다음 계획도 검토 실행 8회를 더 요구했다.
3. 리뷰 → 반영 → 재리뷰 루프에 정지 규칙·예산이 없었다. 위협 모델은 뒤늦게(8/28 밤) 문서에 생겼고 "로컬 위조는 막을 수 없다" 고 스스로 적었는데도 그 뒤 같은 방향의 장치(43·45: 에이전트 35·350만 토큰)를 더 쌓았다.
4. 실행 절차가 사람 손(1,164줄 RUNBOOK, 최소 72개 수동 행동 묶음)에 있고 상태가 워크트리 6개에 흩어져, 관통할 때마다 새 운영 결함이 나온다. 샌드박스가 Orca IPC 를 막아 권한 강제와 lifecycle 자동화가 양립하지 않는다.
5. **그럼에도 impl5 산출물은 지금 close 할 수 있다.** 막는 것은 하네스가 아니라 계획이 스스로 얹은 단계(impl6 전체 교체·§6.6 표본·D-75 (a))다.

**어긋난 것 — 인과의 방향 (무엇이 근본인가):**
- Codex 는 **목표 설정 오류**(비결정적 판정을 결정적 합격 조건으로)를 1순위로, Claude 합성은 **하네스 SHA 결박 + 동결 규칙 부재**(고칠 때마다 관통 무효)를 1순위로 뒀다.
- Claude 반박 단계는 **두 서사 모두** 과장이라고 판정했다(상위 3개 주장 0/3 유지): base 이동은 관통이 찾은 진짜 결함과 **사용자의 spec 재승인(check-6 추가)** 때문이라 동결 규칙으로 사라지지 않고, "동일 게이트 판정" 문구는 관측보다 먼저(8/27) 원 요구에 있었으며, 검토자 면은 8/29 14:41 에 실제로 판정됐고, `gate_verdict` 는 봉투 스키마의 필수 필드다. 또 "위조 저항은 v1 밖" 도 절반만 맞다 — v1 합격 흐름 자체가 "HEAD SHA 에 묶인 증거" 를 요구하고, 4차 리뷰가 뚫은 것(손으로 친 봉투로 게이트 PASS)은 합격 기준의 정확성 문제였다.

**코디네이터 판정 (사실·추정·추천을 나눠서):**
- *사실:* 원 요구 "역할 교체 뒤 동일 artifact 스키마·게이트 판정" 은 **'게이트 판정' 이 결정적 검사인지 LLM 검토 판정인지 정하지 않았다.** 구현은 후자까지 포함하는 쪽을 골랐고, 관측이 그 전제를 깨자 요구를 되묻는 대신 게이트의 기계(표본·제외·봉인)를 바꿨다. 이것이 "설계가 처음부터 틀렸다" 와 "실행이 틀렸다" 의 정확한 경계다 — **틀린 것은 모호한 합격 기준을 확정하는 결정이 한 번도 PM 앞에 올라가지 않은 것**이다.
- *사실:* 얇은 spine·수직 슬라이스·역할 2개·현재 트리 재실행 대조(REQUIRED_CHECK_RERUN)는 옳은 뼈대이고 지금도 동작한다(테스트 398 OK · 라우팅 33/33 · compile --check · parity --report 전부 exit 0). **전면 재작성 대상이 아니다.**
- *추정:* 정지 규칙이 있었다면 28행(2차 리뷰 전량 반영) 또는 36행(D-74) 에서 멈춰 페이로드를 먼저 닫았을 것이다. 위조 저항 층은 그 뒤 별도 단위였을 것이다.
- *추천:* `REVISED_PLAN.md` 의 확인란을 **그대로 채택**하되 impl6 교체는 "선택 1회, 게이트 아님" 으로 둔다(아래 결정 3). 두 분석이 이 지점에서만 갈렸고, 원 요구 문구("합격 조건은 역할 교체 재현")를 존중하면서 비용을 1회로 묶는 절충이다.
