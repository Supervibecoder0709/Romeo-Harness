## 결과 형식

### 1. 최종 판정

다음 중 하나를 선택해줘.

- 그대로 구현 가능
- 소폭 수정 후 구현 가능
- 주요 수정 후 구현 가능
- 구조 재설계 필요

판정 이유는 핵심 근거만 5문장 이내로 작성해줘.

### 2. 반드시 유지할 결정

Claude 계획에서 잘한 결정 중 유지해야 할 내용을 최대 5개로 정리해줘.

각 항목에 다음을 포함해줘.

- 결정
- 잘한 이유
- 관련 요구사항
- 근거 파일 또는 계획 위치

### 3. 발견 사항

중요도가 높은 순으로 최대 8개만 작성해줘.

각 발견 사항은 다음 형식을 사용해줘.

- `ID`
- `등급`
- `문제 또는 강점`
- `근거`
- `실제 영향`
- `최소 수정안`
- `확신도`

등급은 다음 기준을 사용해줘.

- `BLOCKER`: 현재 상태로 구현하면 핵심 목표 달성이나 안전한 진행이 어렵다.
- `MAJOR`: 구현할 수는 있지만 큰 재작업이나 구조적 부채가 예상된다.
- `MINOR`: 구현 시작을 막지는 않지만 품질과 명확성을 개선해야 한다.
- `PREFERENCE`: 객관적인 결함이 아니라 접근 방식이나 표현상의 선호다.
- `HOLD`: 자료가 부족해 현재 판단할 수 없다.

`PREFERENCE`와 `HOLD`는 반드시 수정해야 하는 결함으로 계산하지 마라.

### 4. 요구사항 누락 검사

핵심 요구사항만 대상으로 다음 표를 작성해줘.

| 요구사항 | 계획의 대응 위치 | 상태 | 검증 방법 |
|---|---|---|---|

상태는 다음 중 하나를 사용해줘.

- 충분히 반영
- 일부 반영
- 누락
- V1 이후로 합리적으로 연기
- 판단 보류

### 5. 구현 순서 검사

현재 계획이 다음 최소 흐름을 먼저 완성하는지 판단해줘.

```text
요청 입력
→ 작업 깊이 판단
→ 필요한 워크플로우 선택
→ 계획 또는 실행 방식 결정
→ 실행 결과 검증
→ 상태와 증거 기록
```

순서가 적절하다면 그대로 유지하라고 명시해줘.

문제가 있다면 전체 계획을 다시 쓰지 말고 다음만 제시해줘.

- 앞당겨야 할 단계
- 늦춰야 할 단계
- 합쳐야 할 단계
- 제거하거나 V1 이후로 미뤄야 할 단계

### 6. 최종 수정 목록

다음 세 범주로만 정리해줘.
