## F-08 — 컴파일을 원자적으로

**현상(네 리뷰 원문):** 일반 파일을 먼저 덮어쓰고, skill destination 을 `rmtree` 한 뒤 복사하고,
state 는 마지막에 쓴다. 중간 실패 시 롤백이 없어 두 런타임이 서로 다른 세대의 규칙을 읽을 수 있고
state 가 없을 수도 있다. `_render_settings` 는 산출물 `.claude/settings.json` 을 입력으로 다시 읽어
기대값이 현재 출력에 순환 의존한다.

**요구:**
1. 모든 입력(어댑터 정의·소스 파일·기존 JSON)과 경로를 **쓰기 전에** 검증한다. 검증 실패 = 쓰기 0건.
2. 완성본을 staging 에 만든 뒤 파일 단위 atomic replace 로 반영한다. 도중 실패하면 원래 상태가 남아야 한다.
   (`os.replace` 는 같은 파일시스템에서 원자적이다. 디렉터리 트리는 임시 이름으로 만든 뒤 교체·정리한다.)
3. `_render_settings` 의 순환성을 없앤다. 하네스가 소유하는 것은 `permissions.ask` 와 `permissions.deny`
   뿐이고, 나머지 키는 사용자 것이다. **기대값 계산이 현재 산출물에 의존하지 않게** 하되 사용자 키는 보존해야 한다.
   `check_compiled` 도 하네스 소유 부분만 비교하도록 맞춰라 — 지금은 사용자가 비소유 키를 바꾸면
   그 변경 자체가 기대값이 되어 검사가 무의미해진다.
4. 회귀 테스트: 중간 실패(깨진 심링크 소스·권한 오류 등)를 주입해 **쓰기 0건 또는 완전 롤백**을 확인하고,
   settings 비소유 키 변경이 `check_compiled` 를 통과시키지 못하는지 확인한다.

## F-07 후반 — upstream 고정 커밋과 대조

**현상:** `check_vendor` 는 `source_sha` 를 한 번도 쓰지 않는다. `imports.yaml` 의 `files` 해시와
로컬 바이트만 비교하므로, vendor 파일과 manifest 를 같은 변경에서 함께 바꾸면 통과한다.

**요구:**
1. 고정 커밋의 tree 를 조회해 `imports.yaml` 의 `files`(blob sha)·`modes` 와 대조하는 경로를 만든다.
   `romeo vendor verify-upstream` 같은 별도 동작이 적절하다 — 기존 `romeo vendor check` 는
   네트워크 없이 도는 로컬 검사로 남겨라(CI 가 그걸 쓴다).
2. 결과를 **증거로 남긴다.** 언제·어느 커밋·무엇을 대조했고 결과가 무엇인지. 위치와 형식은 네가 정하되
   `provenance/` 아래가 자연스럽다. 사람이 나중에 "이 대조가 실제로 됐다"를 확인할 수 있어야 한다.
3. 네트워크 실패·rate limit 을 **조용히 통과시키지 마라.** 확인 못 한 것은 확인 못 했다고 보고해야 한다.
4. 테스트는 **네트워크 없이** 돌아야 한다. 응답 파싱과 대조 로직을 네트워크 호출에서 분리하고,
   고정된 샘플 데이터로 검증해라. 실제 조회는 수동 실행으로 한 번 확인하고 그 출력을 커밋 메시지에 남겨라.
