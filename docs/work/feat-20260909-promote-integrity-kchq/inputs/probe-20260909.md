## 이 프로브가 잡은 AC 결함 2건

### ① 판정 5개가 리터럴이 아니라 리터럴 **연결**로 등록된다

`romeo/close.py:751` 이 `check("REVIEW_" + cid, …)` 로 `ENVELOPE_CHECKS` 를 순회하며 판정을 등록한다 —
실제로 인쇄되는 id 는 `REVIEW_ENVELOPE_VALID` 를 비롯한 5개인데, AC-2 가 적은 「문자열 리터럴」 규칙으로는
하나도 잡히지 않는다. 그대로 두면 목록이 실제 판정을 다 담지 못하면서 AC-1 이 참이라고 주장하게 된다.

**반영:** AC-1·AC-2 의 대상을 「리터럴로 등록되는 판정 id」로 좁히고, 리터럴 연결로 만들어지는 판정은
문서의 「파생 판정」 절에 **규칙 한 줄**로 적되 대조 대상이 아님을 명시한다. 규칙이 개별 id 나열보다 정확하고,
아무도 대조하지 않는 자리는 대조하지 않는다고 적는다(§11).

### ② `spec.md` 폴백이 죽은 조건이다

AC-5 가 「`spec.md`(없으면 `charter.md`)」라고 적었는데, `docs/work/` 의 31개 폴더 중 `spec.md` 가 없는 폴더는
0 개다. `charter.md` 를 가진 T2 단위도 `spec.md` 를 함께 갖는다. 폴백은 검토 시점에 발동하지 않는 조건이라
확인할 수 없는 문장이 된다.

**반영:** AC-5 를 `spec.md` 로 한정하고, `spec.md` 가 없는 폴더는 건너뛴다고 적는다.
