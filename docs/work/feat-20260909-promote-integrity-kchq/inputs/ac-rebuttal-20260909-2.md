반례는 모두 확인란 문장을 기준으로 구성한 가상 산출물입니다. 파일 변경과 검사·빌드 실행은 없었습니다.

### AC-1

- 반례: 없음. 실제 판정의 id·수준·출처를 요구하므로 거짓 수준이나 출처를 적은 표는 문장 자체를 충족하지 못합니다. 일부 판정만 담는 누락은 AC-2가 보완합니다.
- 검토 시점: 가능합니다. 최종 문서와 출처 파일을 읽어 행의 내용과 파생 판정 설명을 확인할 수 있습니다.
- 표현: 표의 행과 파생 판정 예외가 구분돼 있습니다. 「각 행」의 대상 범위는 AC-2와 함께 읽으면 한정됩니다.

### AC-2

- 반례: 가령 오류 메시지가 `"RULE: " + detail`인 판정을, **단일 문자열 리터럴이 아닌 표현이라는 이유로 통째로 제외한 목록과 검사기**입니다. 실제 오류의 고정 접두는 `RULE`인데도 목록과 추출 결과에서 함께 빠져 두 집합이 같아집니다.
- 검토 시점: 가능합니다. 다만 같은 소스를 두고 무엇을 추출해야 하는지 해석이 갈리면 검토 결과도 달라집니다.
- 표현: 「리터럴 접두」의 끝 경계가 불명확합니다. 특히 연결 표현 제외가 **판정 id 표현**에 적용되는지, **오류 메시지 전체**에 적용되는지 구분되지 않습니다. 대상 파일은 열거됐지만 포함 집합과 제외 집합의 경계가 겹칩니다.

### AC-3

- 반례: 세 fixture에 공통으로 깨진 링크가 있고, 검사기는 집합 차이와 위조 id를 정상 출력하지만 **최종 종료 코드는 링크 오류만으로 결정하는 구현**입니다. 세 상태 모두 `1`과 위조 id가 나오면서도, 링크 오류가 없는 집합 불일치에서는 `0`이 나올 수 있습니다.
- 검토 시점: 실측 기록으로 확인할 수 있습니다. 다만 제시된 관측 조건만으로는 종료 코드 `1`을 집합 불일치가 발생시켰는지 구별되지 않습니다.
- 표현: 세 위조 상태는 명확하게 열거돼 있습니다. 그러나 「위조한 id가 출력된다」는 사실과 「그 불일치 때문에 실패한다」는 사실은 다릅니다. 뒤의 이유 설명이 앞의 관측 조건보다 강합니다.

### AC-4

- 반례: 없음. **대상 파일의 부재를 검출한다는 한정된 의도**에서는 별도 반례를 찾지 못했습니다. 참조형 링크를 놓치는 것은 명시된 제외 범위입니다.
- 검토 시점: 검사 동작과 fixture 결과는 확인할 수 있습니다. 「이 저장소가 쓰지 않는 표기다」는 검사 기능과 별개인, 저장소 전체의 사용 현황에 관한 주장입니다.
- 표현: 경로 뒤에 `#절이름`이나 링크 제목이 붙었을 때 무엇을 대상 파일 경로로 보는지 불명확합니다. 또한 「이 저장소가 쓰지 않는다」는 전칭 표현의 문서 범위가 없습니다. 범위가 정해지면 **참조형 링크를 사용하는 문서가 있는지**로 반대 사례를 확인할 수 있습니다.

### AC-5

- 반례: id 중복 fixture에서는 요구한 값·폴더 이름을 출력하고 실패하지만, 제목만 같은 fixture에서도 **별도의 ‘제목 중복’ 오류로 실패하는 구현**입니다. 뒤 fixture에는 id 중복 위반이 출력되지 않으므로 문장 조건은 충족합니다.
- 검토 시점: 가능합니다. 다만 뒤 fixture는 특정 메시지의 부재만 확인하므로, 같은 제목 때문에 검사 전체가 실패하는 동작을 배제하지 못합니다.
- 표현: 「양방향」이라고 했지만 앞쪽은 실패 결과를, 뒤쪽은 메시지 부재만 요구합니다. 또한 「각 폴더」가 바로 아래 작업 단위 폴더인지 모든 하위 폴더인지 불명확합니다. 탐색 범위를 정하면 중복 id를 가진 폴더 묶음으로 위반 집합을 특정할 수 있습니다.

### AC-6

- 반례: 없음. 실제 검사한 루트와 실제 대조한 id 개수를 출력한다는 문장대로 읽으면, 허위 경로나 숫자를 출력하는 산출물은 이미 조건을 충족하지 못합니다. 대조의 정확성은 AC-2가 담당합니다.
- 검토 시점: 가능합니다. 실행 당시 작업 디렉터리·명령·출력·종료 코드가 남으면 확인할 수 있습니다.
- 표현: 실행 장소와 인자 조건이 특정돼 있습니다. 별도의 전칭 표현이나 서로 다른 경우가 섞인 문제는 찾지 못했습니다.

### AC-7

- 반례: 기존 승인 확인 판정의 id는 유지하면서, 조건을 **‘승인 기록이 있음’에서 ‘spec.md가 있음’으로 바꾼 구현**입니다. id 집합과 판정 개수는 같지만 승인받지 않은 작업도 종료될 수 있습니다.
- 검토 시점: 기준 커밋이 식별되면 과거 파일과 현재 파일의 비교는 가능합니다. 다만 「승인 커밋」이 어느 승인 기록에 연결되는지, 재승인하면 기준이 바뀌는지가 이 확인란에서는 불명확합니다.
- 표현: **id 집합 불변과 종료 판정의 동작 불변이 같은 뜻으로 이어집니다.** `ENVELOPE_CHECKS` 등 다른 등록 경로도 비교 범위에서 빠져 있습니다. 추가·삭제된 id라는 차집합은 확인할 수 있지만, 같은 id의 조건 변경은 그 집합에 나타나지 않습니다.

### AC-8

- 반례: 두 집합이 다르면 「승격 후보」 줄을 출력한 뒤 **새로운 차단 조건으로 종료 코드 `1`을 반환하는 구현**입니다. 같으면 해당 줄을 출력하지 않습니다. AC-7의 id 집합도 유지하면서, 기존 종료 조건을 충족한 작업까지 끝내지 못하게 할 수 있습니다.
- 검토 시점: 두 상태의 실행 기록으로 확인할 수 있습니다. 다만 어떤 작업 단위와 인자로 실행하는지, 기존 오류로 일찍 종료하는 경우까지 포함하는지가 없습니다.
- 표현: 불일치와 일치의 두 경우를 한 문장에 묶었지만, 각각의 적용 조건이 한정되지 않았습니다. **안내 줄의 유무만 규정하고 기존 종료 결과에 미치는 영향은 열어 둡니다.** 또한 「승격 후보」로 시작한다는 조건만으로는 그 줄의 내용이 실제 불일치를 설명하는지도 확인되지 않습니다.

### AC-9

- 반례: 해당 단계에는 금지된 두 표기가 없지만, **그 단계를 포함하는 상위 작업 묶음(job)에 `continue-on-error: true`가 있는 설정**입니다. 명령은 실행돼도 실패가 자동 검사 전체의 실패로 이어지지 않을 수 있습니다.
- 검토 시점: 파일에서 단계와 금지 표기의 유무는 확인할 수 있습니다. 실제 실행 여부와 실패 전달 여부는 별도의 확인 대상이며, 단계가 존재한다는 사실만으로 확인되지 않습니다.
- 표현: 금지 범위가 「그 단계」에 한정돼 있습니다. 상위 작업의 실패 무시 설정과 조건에 따른 실행 생략은 열거되지 않았습니다. 두 문자열의 부재로 **실패를 무시하는 모든 경우가 배제됐다고 볼 수 없습니다.**

## 요약

- **AC-2:** 고정 id 접두 추출과 연결 표현 제외의 적용 범위가 충돌할 수 있습니다.
- **AC-3:** 다른 검사 오류가 종료 코드 `1`을 만들더라도 제시된 실측 조건을 충족할 수 있습니다.
- **AC-4:** 대상 파일 경로 해석이 불명확하고, 저장소 전체의 참조형 링크 비사용 주장이 섞여 있습니다.
- **AC-5:** 제목만 같은 fixture가 별도 오류로 실패해도 허용되며, 폴더 탐색 범위도 불명확합니다.
- **AC-7:** id 집합 유지가 판정 동작 유지를 보장하지 않고, 승인 기준 커밋의 식별도 불명확합니다.
- **AC-8:** 안내 출력 조건만으로는 새로운 종료 차단을 막지 못하며, 실행 대상과 안내 내용도 한정되지 않습니다.
- **AC-9:** 단계 내부의 두 표기만 금지해 상위 작업의 실패 무시와 실행 생략을 배제하지 못합니다.
## 반영 (2차)

1차 반박을 반영해 고친 확인란을 같은 검토자 런타임에 다시 넘긴 결과다. AC-1·AC-4·AC-6 은 「반례 없음」으로 돌아왔다.

| AC | 지적 | 반영 |
| --- | --- | --- |
| AC-3 | 세 상태에서 종료 코드 1 과 위조 id 가 나와도, 링크 오류 같은 다른 위반이 종료 코드를 만들었을 수 있다 — 집합 불일치가 원인이라는 증거가 아니다 | **수용.** 각 위조를 「다른 위반이 없어 종료 코드 0 을 내는 사본」에서 만들고, 같은 사본에서 **위조 전 0 과 위조 후 1 을 이어 관측**하도록 바꿨다. 차이가 위조에서 나온 것임을 짝이 보인다 |
| AC-5 | 뒤 fixture 가 「id 중복 위반이 인쇄되지 않는다」만 요구해, 제목 때문에 검사 전체가 실패하는 동작을 배제하지 못한다. 폴더 탐색 범위도 불명확하다 | **수용.** 뒤 fixture 의 요구를 **종료 코드 0** 으로 바꾸고, 탐색 범위를 `docs/work/` 바로 아래 폴더로 못 박았다 |
| AC-9 | 단계 안의 두 표기만 금지해, 상위 job 의 `continue-on-error` 를 배제하지 못한다 | **수용.** 그 단계와 그 단계를 담은 job 양쪽에 `continue-on-error` 가 없을 것으로 넓혔다 |
| AC-2 | 「리터럴 접두」의 끝 경계가 없고, 연결 표현 제외가 id 표현에 적용되는지 메시지 전체에 적용되는지 갈린다 | **수용.** 규칙을 하나로 통일했다 — 문자열이 **고정 텍스트로 시작**하면 선두의 첫 공백 앞까지가 id 이고(f-string 의 고정 선두 포함), 변수·연결로 **시작**하면 제외한다 |
| AC-4 | 경로에 `#절이름` 이 붙었을 때 무엇을 대상 파일로 보는지 불명확하다. 「이 저장소가 쓰지 않는다」는 문서 범위 없는 전칭이다 | **수용.** `#` 뒤를 잘라낸 부분을 대상 경로로 명시하고, 전칭의 범위를 `docs/current/` 로 좁혔다 |
| AC-7 | 「승인 기준 커밋」의 식별이 불명확하다 | **수용.** `bin/romeo envelope build` 가 이력에서 찾는 것과 같은 커밋으로 못 박았다 |
| AC-7 | id 집합 유지가 판정 동작 유지를 보장하지 않는다 | **미수용(2회차).** 1차와 같은 이유다 — 동작 보존은 이 단위의 요청 밖이고 회귀 방지 검사가 겨눈다(§12) |
| AC-8 | 안내 출력 조건만으로 새로운 종료 차단을 막지 못한다 | **미수용.** 차단은 `romeo/close.py` 의 `check(` 를 거쳐야 생기고, AC-7 이 그 집합의 동일을 요구한다 — 두 AC 가 함께 닫는다 |
