# M4 — 문서 재사용·승격·지표

> 깊이 **Deep** · 단위 T2 · 모드 delivery · 의도 write · 영역 tooling, docs · 게이트 없음
> 승인 창구는 Tech Spec 의 확인란 하나다(D-60). 이 문서는 승인 대상이 아니다 —
> 다만 「마일스톤 계획」이 비어 있으면 차단 `milestone-plan` 이 승인과 종료를 막는다.

## 왜 이 이니셔티브인가

M4 — 문서를 두 번 만들지 않고, 끝난 사실을 current 로 올리고, 하네스가 자기 지표를 집계한다

- **지금 없는 것:** 하네스는 자기가 무엇을 이미 만들었는지 모른다. `docs/work/` 에 23건이 쌓였지만 검색·1-hop 재개·승격·지표 집계가 전부 사람의 기억과 눈으로 훑기에 의존한다. `docs/current/` 는 비어 있고, 지표 4개는 한 번도 집계된 적이 없다.
- **생기면 무엇이 달라지나:** 같은 일을 두 번 열기 전에 카드가 겹치는 단위를 내밀고, 다음 세션이 폴더를 훑는 대신 한 번의 목록으로 재개하며, 끝난 사실이 작업 단위에 묻히지 않고 `docs/current/` 로 올라오고, 하네스가 자기 분류 정확도를 숫자로 말한다.
- **성공을 무엇으로 아는가:** 계획 §10 #14 의 관찰 가능한 결과 네 가지 — 중복 요청에 `/plan` 이 기존 unit id 를 제시 · `docs/current/` 에 승격 문서 1건 이상 · `romeo metrics` 가 표를 출력 · 깨진 링크 0. 넷 다 명령의 종료 코드로 판정한다(K-51).

## 범위·비범위

- **이 이니셔티브가 하는 것:** 저장소 안의 문서를 **읽어** 검색·재개·승격·집계하는 하네스 자신의 도구 네 가지.
- **하지 않는 것:** 중복·미승격·지표 미달을 **차단**하지 않는다. 이 넷은 전부 사람의 판단이 옳은 경우가 있는 자리라 차단은 정상 경로를 막는다. 드러내는 데까지가 이 이니셔티브의 범위다. 문서의 내용을 자동으로 고치거나 요약하지도 않는다(K-61).
- **다른 이니셔티브에 넘기는 것:** 다른 프로젝트로의 부착·업데이트·롤백은 M5 다. shadow mode 20건 수집과 v1 릴리스 게이트 판정은 §10 #15 다 — 이 이니셔티브는 그 판정이 읽을 지표를 만들 뿐 판정하지 않는다.

## 마일스톤 계획

T2 는 한 번에 끝나지 않는다. **마일스톤마다 무엇이 서면 다음으로 넘어가는지**를 여기 적는다 —
이 절이 비어 있으면 차단 `milestone-plan` 이 승인을 거부한다. 각 마일스톤은 그 자체로 되돌릴 수 있어야 한다.

| # | 마일스톤 | 끝났다고 말할 조건 | 다음으로 넘어가는 관문 | 되돌리기 |
| --- | --- | --- | --- | --- |
| M1 | 재사용 검색 — `romeo find` 와 그것을 스스로 부르는 카드 | 제안의 `reuse_hits` 가 비어 있어도 카드가 겹치는 단위 id 를 인쇄하고, 겹치지 않으면 인쇄하지 않는다 | 검색 결과가 실제로 카드에 남는 것을 관통 1회로 확인 (이 폴더의 `spec.md`) | `romeo/find.py`·`tests/test_find_reuse.py` 삭제 + 3개 파일 revert |
| M2 | 1-hop 재개 — `romeo context <id>` | 한 단위 id 로 다음 세션이 읽어야 할 파일 목록(spec·evidence·검토·상위 문서)을 출력하고, 그 목록에 없는 파일을 읽지 않아도 재개가 되는 것을 1회 실측 | M1 의 검색이 그 id 를 먼저 찾아 준다 — 검색 없이 context 만으로는 「어느 id 인가」가 남는다 | 하위 명령 제거 |
| M3 | 승격과 무결성 — `/plan-close` 의 `docs/current/` 승격 후보 제안 · `decisions.md` append · 링크/ID 무결성 검사 | `docs/current/` 에 승격 문서 1건 이상이 서고, 의도적으로 깨뜨린 링크·중복 slug fixture 에서 검사기가 실패한다 | 승격 대상 판정 규칙을 M2 까지의 실사용으로 정한다 — 지금은 미정이라 여기서 결정한다 | 승격 문서 삭제 + 검사 제거. 원본은 작업 단위에 그대로 남으므로 소실 없음 |
| M4 | 지표 — `romeo metrics` 가 분류 수정률·gate 누락·T0 처리 시간·재분류율 4개를 집계 | 표가 출력되고, 각 숫자의 원본 파일을 명령이 함께 인쇄한다(숫자만 믿지 않는다, K-63) | M1~M3 이 만든 문서·링크가 집계의 입력이다. 원본 데이터 부재가 확인되면 그 지표는 「미집계」로 정직하게 인쇄한다(K-68) | 하위 명령 제거 |

- **첫 마일스톤을 먼저 하는 이유:** 나머지 셋이 전부 「이미 무엇이 있는가」를 아는 것에서 출발한다. 또한 넷 중 유일하게 지금 절차가 **이미 요구하고 있는데 집행이 없는** 것이라, 새 요구를 더하지 않고 기존 요구를 세우는 일이다(§11·§12).
- **중간에 멈춰도 되는 지점:** 네 마일스톤 사이 전부. 각 마일스톤이 독립된 하위 명령이나 검사이고, 앞의 것이 없어도 뒤의 것이 깨지지 않는다 — 다만 M2 는 M1 없이 쓰임새가 줄고, M4 는 M1~M3 이 만든 데이터가 없으면 집계할 것이 적다.

## 제약·전제

- **바꿀 수 없는 것(기술·조직·일정):** 표준 라이브러리 + PyYAML 만 쓴다(M0 부터의 제약). 코어는 벤더 중립이라 도구명·모델명을 넣지 않는다(C-C6). 승인 창구는 Tech Spec 의 확인란 하나다(D-60).
- **지금 참으로 가정하는 것:** 네 조각이 서로 독립적으로 되돌릴 수 있다 · 지표 4개의 원본 데이터가 evidence·fixture 안에 있다 · `ripgrep` 이 없는 환경에서도 표준 라이브러리로 충분히 빠르다(문서 23건 규모).
- **그 가정이 틀리면 무엇이 무너지나:** 원본 데이터가 없으면 M4 의 지표 일부는 「미집계」로 남는다 — 이니셔티브가 무너지는 것이 아니라 그 칸이 정직해진다(K-68). 독립성 가정이 틀리면 마일스톤 경계를 다시 그어야 하고, 그때는 `/plan` 재분류로 이 charter 의 계획표를 고친다(D-09).

## 위험·중단 조건

- **가장 큰 위험:** 드러내기가 조용히 차단으로 자라는 것. 검색·무결성 검사는 「경고를 오류로 올리자」는 압력이 자연스럽게 붙는 자리인데, 거짓 양성 하나가 정상 경로를 막으면 사람은 검사를 끄는 쪽을 배운다(K-31 「경고까지만」).
- **중단 조건(무엇을 보면 멈추는가):** ① 같은 마일스톤에서 관통이 연속 2회 실패하면 3회차 전에 멈춘다(§10 반복 중단) · ② 검색·검사의 거짓 양성이 실제 작업을 한 번이라도 막으면 그 조각을 경고로 강등하고 재검토한다 · ③ 지표 원본 데이터가 절반 이상 부재로 확인되면 M4 를 열지 않고 무엇을 먼저 기록해야 하는지부터 정한다.
- **되돌리기:** 마일스톤마다 `git revert <구현 커밋>`. 이 이니셔티브는 운영 상태·외부 상태·비용을 건드리지 않고 저장소 안 파일만 만든다. `docs/current/` 승격은 복사이므로 원본이 작업 단위에 그대로 남는다 — 되돌려도 소실이 없다.
