### AC-1

- 반례: 인용문·코드 예시 속 `모든`에도 문자열만 일치하면 경고하는 구현. 명시된 패턴 탐지와 출력은 충족하지만, 실제 전칭 명제가 아닌 문장까지 경고한다.
- 검토 시점: 현재 출력과 종료 코드는 검토 시점에 확인할 수 있다. 다만 “정책표에서 패턴을 지우면 경고가 사라진다”는 변경 전후 실행 증거가 필요하며, 최종 파일만으로는 확인할 수 없다. “종료 코드는 그대로”도 비교 기준이 명시되지 않았다.
- 표현: `패턴을 찾으면`은 AC×패턴의 전칭 조건인데, 한 AC에 여러 패턴이 있을 때 패턴마다 경고하는지 정의되지 않았다. 여집합을 “일치했지만 경고되지 않은 AC·패턴 쌍”으로 볼 수 있으나, 중복·겹침·이어지는 줄의 끝이 정해지지 않아 집합을 확정할 수 없다. 양성·정책 변경·음성 사례도 한 AC에 섞여 있다.

### AC-2

- 반례: 각 `### AC-n` 제목만 있고 세 항목의 내용은 전부 비어 있는 반박 파일. 모든 제목이 있으므로 경고 없이 승인이 기록되지만, 실제 반박은 수행되지 않았다.
- 검토 시점: 파일 유무, 출력, `status`와 `approved_at`은 검토 시점에 확인할 수 있다. 반박이 실제로 수행되었는지는 이 AC로 확인할 수 없다. 여러 파일이 일치할 경우 어떤 파일을 적용했는지도 판별할 수 없다.
- 표현: “확인란의 AC마다”는 전칭이다. 여집합은 “확인란 AC ID − 반박 파일의 절 ID”로 만들 수 있지만, 여러 파일의 합집합 여부·중복 절·ID 순서·`그대로`의 형식이 정의되지 않았다. 파일 없음·일부 누락·전부 존재의 세 경우도 한 문장에 섞여 있다.

- 표현: 명시적 전칭은 없지만 “본문이 말한다”의 충족 기준이 의미인지 단어 존재인지 불명확하다. “그 단계 본문만”은 검사 입력의 전칭 제한인데, 공용 helper나 간접 입력까지 포함하는지 정해지지 않았다. 문서 순서·본문 내용·검사 결합이 한 AC에 섞여 있다.

### AC-4

- 반례: 정본 브리프가 `<id>`만 포함하고 반례·검토 시점·표현 또는 “확인란만 읽기” 지시는 전혀 없는 파일. 매핑과 compile 산출물까지 정상이어도 반대 독자 역할은 수행되지 않는다.
- 검토 시점: 파일·매핑·compile 산출물은 확인할 수 있다. enforcement 문자열을 복사했다는 사실은 확인 가능하지만, 실제 실행에서 쓰기가 차단되었다는 사실은 별도 거부 실측 없이는 확인되지 않는다.
- 표현: “자리표시자는 `<id>` 하나”는 한 종류인지 한 번의 출현인지 모호하다. `-o`/파일은 런타임별 선택 관계가 불명확하고, “같은 줄”도 문자 동일성인지 의미 동일성인지 정해지지 않았다. `core/`에 도구명·모델명이 “없다”는 전칭은 금지어 집합이 열거되지 않아 여집합 검색으로 완결할 수 없다. 서로 다른 다섯 요구도 한 AC에 묶여 있다.

- 검토 시점: 카탈로그 존재와 검사에서 문자열을 읽는지는 검토 시점에 확인할 수 있다. 다만 “한 줄 설명”의 의미적 정확성은 기대 내용이 없어 확인할 수 없다.
- 표현: 두 코드의 집합은 닫혀 있다. 그러나 어느 코드가 어느 명령 출력과 대응해야 하는지 명시하지 않아, 두 출력의 합집합만 비교해도 충족된 것으로 해석될 수 있다. 카탈로그 형식과 검사 결합도 한 AC에 섞여 있다.

### AC-6

### AC-7

## 반영

이 반박은 판정이 아니라 입력이다. 아래는 **사람(코디네이터)이 읽고 확인란을 고친 결과**다 — 지적을 받고도 고치지 않은 것은 이유와 함께 적는다.

**고친 것 — AC-1~8 전부.**

| AC | 지적 | 어떻게 고쳤나 |
| --- | --- | --- |
| AC-1 | 다중 일치·줄 경계·종료 코드 비교 기준이 불명확 | 「맞은 패턴마다 한 줄」·「종료 코드는 0」 으로 명시. 정책표 판별은 「임시 사본에서 패턴 하나를 지우면 **그 패턴의 경고만 사라지고 나머지는 남는다**」를 한 실행 안에서 보이게 해, 변경 전후 실행 증거 없이 검토 시점에 관측되게 옮겼다 |
| AC-2 | 복수 파일 처리 규칙이 없다 · 빈 절이 통과한다 | 「`inputs:` 목록 순서상 첫 항목 하나」로 닫고, id 인쇄 순서를 「확인란에 나온 순서」로 고정. 빈 절은 **의도된 한계**로 확인란 한계 ④ 에 적었다 |
| AC-3 | 「본문이 말한다」의 충족 기준이 단어인지 의미인지 불명 | 검사가 보는 것을 **접두 문자열 동일성 하나**로 좁히고, 세 항목의 존재는 검토자가 읽는다고 나눴다 |
| AC-4 | 브리프 내용이 검증되지 않는다 · C-C6 금지어 집합이 열려 있다 | 브리프 본문이 말해야 할 것 넷을 ① 로 열거하고, C-C6 판정을 **기존 벤더 중립 검사**에 넘겨 이 AC 가 금지어를 새로 열거하지 않게 했다 |
| AC-5 | 코드별 명령 대응이 없어 합집합 비교로도 충족된다 | `AC_UNIVERSAL`↔`validate`, `AC_UNREBUTTED`↔`approve` 로 **각각** 대조하게 명시 |
| AC-6 | 「기존」의 기준이 없다 · skip 으로 비워도 exit 0 이다 | **승인 커밋** 대비 `tests/` diff 와 **검사 개수 하한**(`Ran <N>`, 승인 시점 실측 929)을 더했다. 반박이 요구한 「기준 SHA」를 frontmatter 의 `base_sha` 로 쓸 뻔했는데, 이 저장소는 승인이 `base_sha` 를 더는 적지 않고 승인 커밋을 이력에서 찾는다(체크리스트 38) — 반박은 확인란만 읽으므로 이런 저장소 사실은 잡지 못한다 |
| AC-7 | 순서·최초·횟수·인과를 사후 검토할 수 없다 | 「누가·언제·몇 번」을 걷어내고 **파일의 존재와 그 파일이 든 커밋**(승인 커밋이거나 그 조상)으로 바꿨다. 이 저장소가 `feat-20260904-gate-fixture-coverage-q3wy` 에서 D-80 재승인으로 닫았던 결함과 같은 모양이다 |
| AC-8 | 아직 관측되지 않은 통과율까지 해소된다 · 「활성 단위」는 종료 시 거짓이 된다 | Q-87 을 「반대 독자 부재」(해소)와 「1회차 통과율」(새 행 · 10개 단위 관측)로 갈랐고, progress 요구를 「이 단위 id 를 담는다」로 완화해 종료 뒤에도 참이게 했다 |

**승인 전 프로브가 그 뒤에 잡은 것 (반박이 잡을 수 없었던 자리)**

반박은 확인란만 읽으므로 **저장소의 사실**과 어긋나는 AC 는 잡지 못한다. 프로브가 그 자리를 둘 잡았다.

- **AC-6·AC-7 의 「기준 SHA」.** 반박은 「비교 기준이 없다」까지 잡았고, 그 기준으로 frontmatter 의 `base_sha` 를 쓸 뻔했다 —
  이 저장소는 승인이 `base_sha` 를 더는 적지 않고 승인 커밋을 이력에서 찾는다(체크리스트 38 · `romeo/docs.py` 의 `approval_commit`). **승인 커밋**으로 고쳤다.
- **AC-4 ⑤ 의 C-C6.** 「기존 벤더 중립 검사가 판정한다」로 썼는데, 그 검사(`TestVendorNeutral`)는 `core/roles/*.yaml` 과 결과 계약 스키마만 보고 절차 파일을 덮지 않는다.
  게다가 `core/workflows/plan/SKILL.md` 에는 원래부터 「실행기(Claude·Codex)에 중립이다」라는 문장이 있어 **파일 전체를 보는 검사는 기존 상태에서도 실패한다**.
  요구를 「이 단위가 새로 넣은 단계 본문에만 도구명이 없다」로 좁혔다.

**고치지 않은 것**

- **AC-4 를 여러 AC 로 쪼개지 않았다.** 반박은 다섯 요구가 한 AC 에 묶였다고 지적했다. 쪼개면 AC 번호가 밀려 **이 파일의 `### AC-n` 절과 확인란 AC id 의 대응이 깨진다** —
  반박은 실제 실행의 기록이므로 절 번호를 손으로 옮겨 적으면 그 기록이 위조가 된다. 대신 다섯 요구를 ①~⑤ 로 갈라 각각이 독립 명제가 되게 했다.
  AC-2·AC-5·AC-6 의 「여러 경우가 한 문장에 섞였다」도 같은 이유로 번호를 유지하고 문장만 갈랐다.
- **AC-3 의 「문자열이 있어도 단계가 실제로 실행된다는 보장이 없다」.** 이 단위의 설계가 그렇다 — 경고까지만이고 절차는 사람이 밟는다(확인란 「무엇을」).
  실행되었다는 것은 AC-7 의 산출물이 말한다. 실행을 강제하려면 차단이어야 하고, 차단은 이 단위가 명시적으로 뺀 것이다.
- **AC-1 의 인용문·예시 거짓 양성.** 경고라 정상 경로를 막지 않는다. 확인란 한계 ⑤ 로 적었다.
- **AC-2 의 「빈 절도 통과」·AC-5 의 「설명 정확성」·AC-4 의 「실제 쓰기 차단 실측」.** 셋 다 기계가 볼 수 없는 의미 판정이라 검토자와 사람에게 남긴다 —
  확인란이 그 자리를 명시했다(「검토자가 읽는다」).
