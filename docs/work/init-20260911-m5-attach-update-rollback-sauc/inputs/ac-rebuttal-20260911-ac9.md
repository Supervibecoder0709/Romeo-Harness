### AC-9

- 반례: 미등록 리비전에 종료 코드 1과 다른 오류 finding을 반환하면서, 출력의 ‘지원 오류 ID 목록’에 `ATTACH_REVISION_UNKNOWN`을 넣는 구현. 문자열 포함은 충족하지만 실제 오류 분류는 틀리다.
- 검토 시점: 검토 시점에 확인 가능한 명제이며 시간 순서 요구는 없다. 다만 이 문장만으로는 대상 하네스 저장소와 판정 명령이 특정되지 않는다.
- 표현: 조건에 맞는 입력 전체를 대상으로 하며, ‘실재하지 않음’은 이미 존재 집합의 여집합이다. 다만 로컬에 보유한 커밋 기준인지 원격 저장소까지 포함하는지 불명확하다. 서로 다른 두 경우의 혼합은 없다.

## 요약

- AC-9: 실제 finding과 단순 문자열 포함을 구별하지 않으며, 존재 여부의 기준 저장소·범위와 판정 명령이 불명확하다.
## 반영

- **AC-9** — 「실재하지 않음」의 기준이 로컬인지 원격을 포함하는지 불명확하다는 지적을 받아
  **판정 명령을 실행한 하네스 저장소의 로컬 이력**으로 못박고, 판정 수단을 `git cat-file -e <값>` 으로 적었다.
  원격만 가진 커밋은 이 기준에서 「없음」이라는 것도 문장에 넣었다.
  finding id 는 이미 조건에 있었다 — 단순 문자열 포함과 실제 finding 을 구별하라는 지적은
  `ATTACH_REVISION_UNKNOWN` 을 **출력이 담는다**는 형태로 이미 만족한다. 대상 하네스 저장소와 판정 명령이
  특정되지 않는다는 지적은 수용 기준 머리의 「판정 명령은 하네스 저장소 안에서 실행한다」가 덮는다.
