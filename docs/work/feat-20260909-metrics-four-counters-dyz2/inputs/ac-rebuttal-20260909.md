### AC-1

- **반례:** 정본의 네 지표를 이름 변경·삭제에 맞춰 정확히 한 행씩 출력하면서, 미등록 지표인 `하네스 준수율 100%`를 추가한다. 등록 지표에 관한 조건은 충족하지만, 기대한 네 줄 표에 근거 없는 숫자가 붙는다.
- **검토 시점:** 완료 후 확인 가능하다. 정본 변경 전후의 입력과 출력이 남으면 이름 변경·삭제 반영도 확인할 수 있다. 다만 정본의 파일 위치는 이 확인란에 특정되지 않았다.
- **표현:** “등록된 지표마다 정확히 한 행”은 등록 지표의 누락·중복만 제한한다. **등록되지 않은 지표 행이라는 여집합**은 금지하지 않는다.

### AC-2

- **반례:** 같은 이력 배열의 서로 다른 항목에서 시작·종료 시각을 잘못 짝지어 `70초`를 계산하고, 실제 사용한 파일 경로와 두 키 이름을 출력한다. 경로·키는 맞지만 배열의 어느 항목인지 없어 잘못된 짝을 식별하거나 계산을 재현하기 어렵다.
- **검토 시점:** 완료 후 출처와 계산 대상을 대조할 수 있다. 다만 과거 실행을 검토한다면 “실행 시점에 경로가 실재했다”는 사실은 현재 파일 존재만으로 확인되지 않으며, 당시 입력을 확인할 근거가 필요하다.
- **표현:** 사건 있음과 0건의 출처 형식이 한 AC에 들어 있다. 0건 예외가 경로·키·실재 요건 중 어디까지 대체하는지 불명확하다. “빈 칸 없음”은 **채워졌지만 대상을 특정하지 못하는 출처**를 배제하지 않는다.

### AC-3

- **반례:** 기록 기능이 없어 실제 발생 여부를 알 수 없는데 `미집계 — 재분류가 한 번도 발생하지 않음`을 출력하고, 사건을 넣은 입력에서는 숫자를 출력한다. 두 분기는 충족하지만, 사유에서 다시 “기록 없음”을 “발생 없음”으로 단정한다.
- **검토 시점:** 두 입력과 각각의 출력이 남으면 완료 후 확인 가능하다. 그러나 `미집계`와 사유의 존재만 확인해서는 **그 사유가 관측 근거와 맞는지** 확인되지 않는다.
- **표현:** 0건과 1건 이상은 사건 수가 정해지면 서로의 여집합이다. 다만 적용 대상은 “정본이 표시한 지표”로만 지칭되고, “관측 사건”이 계산에 필요한 정보까지 갖춘 유효한 기록을 뜻하는지도 이 절에서는 불명확하다.

### AC-4

- **반례:** T0 시각 차이인 `70,000밀리초`를 단위 변환 없이 `70,000초`로 출력한다. 실행 때 원본을 읽고 시각 변경에 따라 값도 달라지므로 조건을 충족하지만, 결과는 실제의 1,000배다.
- **검토 시점:** 원본 변경 전후의 입력·출력으로 반응 여부는 확인 가능하다. “승인 전 프로브에서 실측”은 과거 계획 단계의 설명으로, 완료 구현의 성질과 별개이며 현재 코드만으로 그 시점을 확인할 수 없다.
- **표현:** “숫자가 서는 지표”가 현재의 세 지표인지, 사건을 넣으면 숫자가 되는 재분류율까지 포함하는지 불명확하다. “변경 하나에 값이 달라짐”은 **계산식·단위가 틀린 결과를 배제하지 않는다**. 중앙값에 관한 부수 설명도 구현에 요구하는 조건과 섞여 있다.

### AC-5

- **반례:** gate 누락이 있으면 확인 키 입력을 기다린 뒤 종료 코드 0으로 끝난다. 두 입력 모두 0으로 종료하는 시연이 가능하고 종료 코드도 지표값과 무관하지만, 자동 실행에서는 입력 대기로 다음 절차가 멈춘다.
- **검토 시점:** 종료 코드와 입력 대기는 완료 후 확인 가능하다. 다만 gate 누락 두 경우의 종료 기록만으로 다른 지표값이나 입력 없는 실행 환경까지 확인되지는 않는다.
- **표현:** “지표의 값”은 네 지표 전체에 대한 전칭 표현인데, 제시된 실행 사례는 gate 누락뿐이다. 위반 사례라는 여집합을 **종료 코드 변화**로만 살피면, 같은 코드로 끝나면서 입력을 기다리는 차단은 남는다.

## 요약

- **AC-1:** 등록 지표 조건을 충족하면서 미등록 지표 행을 추가할 수 있다.
- **AC-2:** 경로·키만으로 반복 기록의 실제 계산 대상을 특정하지 못하며, 0건 예외의 적용 범위도 불명확하다.
- **AC-3:** `미집계` 사유가 기록 부재를 사건 부재로 잘못 단정해도 배제되지 않는다.
- **AC-4:** 원본 변경에 반응하는 잘못된 계산을 허용하며, 대상 지표와 과거 프로브 설명의 경계가 불명확하다.
- **AC-5:** 종료 코드가 같아도 입력 대기로 절차를 막을 수 있고, 전칭 요구보다 제시된 확인 범위가 좁다.

## 반영 (2026-09-09 · 사람이 읽고 고친 것)

반박은 판정이 아니라 입력이다. 다섯 지적을 다 받아 AC 를 고쳤다.

| AC | 지적 | 고친 것 |
| --- | --- | --- |
| AC-1 | 「등록된 지표마다 정확히 한 행」은 등록 지표의 누락·중복만 막고, **미등록 행이 끼는 여집합**은 막지 않는다 | 「행의 **집합이** 정본의 집합과 같다」로 바꿔 여집합을 닫았다. 정본의 자리(`romeo/metrics.py`)를 확인란에 명시해 검토자가 찾을 수 있게 했다 |
| AC-2 | 경로·키만으로는 실제 계산 대상을 특정하지 못한다(같은 배열의 다른 항목을 잘못 짝지어도 통과) · 0건 예외가 어디까지 대체하는지 불명확 | 사건 1건 이상과 0건의 **인쇄 형식을 각각 못박고**, 「어느 두 시각을 뺐는지 알아야 손으로 다시 셀 수 있다」는 목적을 문장에 넣었다. 짝짓기 오류 자체는 AC-4 ① 의 독립 재계산이 막는다 |
| AC-3 | `미집계` 사유가 **기록 부재를 발생 부재로 단정**해도 배제되지 않는다 | 「사유는 관측한 것만 말한다」를 AC 에 넣고, 「그런 일이 일어난 적 없다」를 사유에서 명시적으로 금지했다. 그 단정을 허용하면 미집계를 두는 이유 자체가 사라진다 |
| AC-4 | 원본 변경에 **반응하지만 단위·계산이 틀린** 구현(70,000ms 를 70,000초로)을 허용한다 · 「숫자가 서는 지표」의 범위가 불명확 · 프로브 설명이 요구와 섞였다 | ① **집계 코드를 부르지 않는 독립 재계산 대조**를 추가해 단위·짝짓기 오류를 닫았다. 대상을 「그 실행에서 값이 숫자로 인쇄된 지표」로 바꿔 실행 시점에 정해지게 했다. 중앙값에 관한 부수 설명은 AC 에서 빼고 `probe-20260909.md` 에만 남겼다 |
| AC-5 | 종료 코드가 같아도 **입력 대기**로 절차를 막을 수 있다 · 「지표의 값」이 전칭인데 실측 사례는 gate 누락뿐 | 「표준 입력이 닫힌 비대화형 실행에서 사람의 입력을 기다리지 않고 끝난다」를 넣고, 검사 명령을 `bin/romeo metrics < /dev/null` 로 바꿨다. 실측 대상에 「어떤 지표가 미집계인 트리」를 더해 gate 누락 한 경우로 좁혀지지 않게 했다 |

**받지 않은 지적은 없다.** AC-2 의 「과거 실행을 검토한다면 실행 시점의 경로 실재를 현재 파일로 확인할 수 없다」는
문장을 「그 실행이 읽은 트리에 실재한다」로 바꿔 실행과 트리를 묶는 것으로 대신했다 —
검토자는 그 실행의 입력 트리를 함께 받으므로 확인 수단이 있다.
